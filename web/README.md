# Исторический архив · todo100.ru

Next.js 16, React, TypeScript. Лента и параллельные линии, поиск по всем
годовым хронологиям, фильтры, страницы событий и исходные Markdown-документы.

## Локальная работа

Требуется Node.js 24. Из папки `web`:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:3100. По умолчанию архив читается из родительской папки.
Для другого расположения задать `ARCHIVE_ROOT` — абсолютный путь к каталогу
с подпапками `Russia`, `USA`, `Common`. При обновлении файлов индекс
перечитывается автоматически. Поиск учитывает все слова запроса без учёта
регистра и различия е/ё; морфологического поиска пока нет.

```sh
npm test
npm run audit:archive
npm run typecheck
npm run build
npm start
```

Отчёт импорта сохраняется в `reports/import.json`. Он также доступен в разделе
«Об архиве». Исходные файлы приложение открывает только для чтения.

## Docker

Из папки `web`:

```sh
docker compose up -d --build --wait
docker compose logs --tail=100 web
curl -f http://127.0.0.1:3100/api/health
```

Порт опубликован только на loopback. `WEB_PORT` позволяет выбрать другой порт.
Контейнер работает от непривилегированного пользователя, архив подключён
тремя отдельными папками только для чтения. PostgreSQL пока не требуется.
Пользователь контейнера — `node` (UID 1000). На сервере публикуемые копии
файлов должны иметь права чтения `0644`, папки — `0755`. При копировании
новых файлов использовать `install -m 0644`; исходный архив менять не нужно.

## Размещение

Приложение: `/opt/history-archive/web` на `91.99.238.7`.
Сведения о первом размещении и проверках: [deploy/STATUS.md](deploy/STATUS.md).
Текущая учётная запись публикации — `deploy@91.99.238.7`.
Права и разрешённые команды описаны в [deploy/ACCESS.md](deploy/ACCESS.md).
Активный архив: `/opt/history-archive/content/current/{Russia,USA,Common}`.
DNS `todo100.ru` направлен на `155.212.175.209`.

Маршрут: посетитель → HTTPS на 155.212.175.209 → проверяемый HTTPS
на 91.99.238.7 → 127.0.0.1:3100 → контейнер Next.js.

В `deploy/` находятся отдельные конфигурации Nginx для обоих серверов.
HTTP-варианты используются при первом выпуске сертификатов. Постоянные
конфигурации поддерживают автоматическое продление через webroot
`/var/www/history-acme`: прокси сначала ищет локальный ACME-файл, затем
передаёт запрос основному серверу. Сертификаты выпускаются отдельно
на каждом сервере; закрытые ключи не передаются.

Образ собирается локально: `docker build -t history-archive:latest web` из
корня репозитория. Для переноса можно использовать `docker image save`,
`scp` и `docker image load`; затем `docker compose up -d --no-build --wait`.
Конфигурации Nginx устанавливаются отдельными файлами `todo100.ru`,
после `nginx -t` выполняется `systemctl reload nginx`.

Для обычного обновления сделать commit и push в `main`: отдельный workflow
публикует Markdown, другой — код сайта. При совместной правке код и материалы
публикуются одной операцией. Снимки и прежние образы сохраняются; неуспешное
локальное переключение автоматически откатывается. Подробности и ручной запуск:
[deploy/README.md](deploy/README.md). Описанный выше перенос образа нужен для
первого размещения или административного восстановления. На рабочем сервере
используется защищённый Compose из `/etc/project-deploy`, а не локальный файл.

## Модель данных

`src/lib/model.ts` задаёт EventRepository и единый формат события.
`repository.ts` реализует чтение Markdown, `importer.ts` извлекает записи,
`dates.ts` хранит исходные подписи и вычисляет интервалы для сопоставления.
Границы неполных дат используются только для отбора; они не показываются
как установленные дни. Старые блоки без `####` сохраняются целиком.

ID строится из категории, исходной даты и заголовка. Правка тела записи
сохраняет ID. Правка даты или заголовка меняет адрес; перед появлением
редактора и пользовательских связей нужен постоянный реестр ID.
База подключается новой реализацией EventRepository. План: [PLAN.md](PLAN.md).

Необходимые следующие этапы: постоянные ID, редактор с аутентификацией,
сохранённые подборки, PostgreSQL, подготовка черновиков с помощью ИИ.
