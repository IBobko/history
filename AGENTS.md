# Инструкция по добавлению исторических событий через `timeline.py`

Тебе нужно оформить историческое событие или несколько событий в формате хронологической ленты Markdown и добавить их в соответствующие файлы **только через скрипт `tools/timeline.py`**.

Ты работаешь внутри репозитория исторического проекта.

## 1. Основной принцип работы

Разделяй две операции:

1. **Смысловая операция:** подготовить корректное описание исторического события.
2. **Механическая операция:** вставить событие в нужный годовой файл, объединить его с другими событиями той же даты и расположить даты в хронологическом порядке.

Смысловую операцию выполняешь ты.

Механическую операцию выполняет только скрипт:

```bash
python tools/timeline.py
```

**Не вставляй событие непосредственно в файлы `Russia/*.md`, `USA/*.md` или `Common/*.md`.**

**Не ищи вручную место вставки.**

**Не переставляй существующие блоки вручную.**

**Не добавляй разделители `---` вручную.**

Для каждого самостоятельного события:

1. Определи дату события.
2. Определи историко-географическую категорию.
3. Определи файл года начала события.
4. Подготовь содержимое `tools/event.md`.
5. Вызови `tools/timeline.py`.
6. Проверь результат через Git diff.

---

## 2. Порядок выполнения

### Шаг 1. Определи дату

Сформулируй дату или период в том виде, в котором он должен отображаться в заголовке `###`.

Например:

```text
17 августа 1998 года
```

```text
11 июня — 5 октября 1998 года
```

```text
июнь 1991 года
```

Не добавляй перед датой символы `###`: скрипт создаёт заголовок даты самостоятельно.

### Шаг 2. Определи целевой файл

Папку выбирай по историко-географической принадлежности события:

* `Russia/` — Россия, Российская империя, РСФСР, СССР или Российская Федерация;
* `USA/` — история Соединённых Штатов Америки. Все события, происходящие в США или непосредственно относящиеся к истории США, размещай только в этой папке;
* `Common/` — другие государства, международные отношения, международные войны, международные организации и глобальные процессы.

Имя файла должно соответствовать году начала события:

```text
Russia/1998.md
```

```text
USA/1890.md
```

```text
Common/1945.md
```

Если целевой файл отсутствует, создай пустой файл:

```bash
mkdir -p Russia
touch Russia/1998.md
```

Не помещай событие в файл года окончания продолжительного события.

### Шаг 3. Создай `tools/event.md`

Запиши в `tools/event.md` только одно самостоятельное событие.

Файл должен начинаться с заголовка четвёртого уровня:

```markdown
#### [Краткое название события]
```

После него размести основной текст события.

В `tools/event.md` не должно быть:

* заголовка даты `###`;
* разделителя `---`;
* нескольких самостоятельных событий;
* пояснений о том, куда необходимо вставить событие;
* команд для скрипта;
* служебного комментария для пользователя.

### Шаг 4. Вызови скрипт

Находясь в корне репозитория, выполни:

```bash
python tools/timeline.py Russia/1991.md \
  --date "27 октября 1991 года" \
  --event tools/event.md
```

Путь к файлу и значение `--date` замени на фактические.

Скрипт должен:

* найти соответствующую дату;
* создать блок даты, если его ещё нет;
* добавить событие к существующей дате;
* расположить даты в хронологическом порядке;
* сохранить резервную копию файла с расширением `.bak`.

### Шаг 5. Проверь изменение

После выполнения команды проверь изменения:

```bash
git diff -- Russia/1991.md
```

Убедись, что:

* событие добавлено в правильный файл;
* текст события не повреждён;
* дата отображается правильно;
* событие находится под нужной датой;
* существующие события не удалены;
* в файл не попало содержимое другого события;
* не возникло необъяснимых изменений текста.

Автоматическая перестановка существующих блоков в правильный хронологический порядок допустима.

Если скрипт повредил или удалил существующее содержимое, восстанови файл из резервной копии:

```bash
cp Russia/1991.md.bak Russia/1991.md
```

После восстановления сообщи об ошибке. Не пытайся скрыть её ручным редактированием годового файла.

## 3. Несколько событий

Каждое самостоятельное событие добавляй отдельным вызовом скрипта.

Не помещай несколько самостоятельных событий в один `tools/event.md`.

Правильная последовательность:

1. Записать первое событие в `tools/event.md`.
2. Вызвать `timeline.py`.
3. Проверить результат.
4. Перезаписать `tools/event.md` вторым событием.
5. Снова вызвать `timeline.py`.
6. Снова проверить результат.

Если несколько событий произошли в один день, передавай одинаковое значение `--date`.

Скрипт объединит их внутри одного блока даты:

```markdown
### 12 июня 1991 года

#### Президентские выборы РСФСР

[Текст первого события.]

#### Выборы мэра Ленинграда

[Текст второго события.]
```

Каждое самостоятельное событие должно иметь собственный заголовок `####`.

Даже если в этот день имеется только одно событие, всё равно используй заголовок `####`. Это обеспечивает единый формат для новых записей.

## 4. Правила датировки

### Событие в конкретный день

Если событие произошло в конкретный день, используй одну дату:

```text
17 августа 1998 года
```

Назначение, избрание или вступление в должность является событием конкретного дня:

```text
6 ноября 1991 года
```

В тексте:

```markdown
**Евгений Примаков** был назначен директором Центральной службы разведки СССР.

На этой должности он оставался до 26 декабря 1991 года.
```

Дата назначения описывает событие.

Период пребывания в должности описывает возникшее после него состояние.

Не превращай дату назначения в период только потому, что человек занимал должность некоторое время.

### Период пребывания у власти

Период используй только тогда, когда предметом события является всё пребывание человека, правительства, органа или администрации у власти:

```text
11 сентября 1998 года — 12 мая 1999 года
```

Такое событие должно описывать деятельность, особенности или историческую роль всего периода, а не только назначение.

### Продолжительное событие

Если продолжительность является существенной частью события, указывай начало и окончание:

```text
11 июня — 5 октября 1998 года
```

Если период находится внутри одного месяца:

```text
11–14 июня 1998 года
```

Если известны только месяцы:

```text
июнь — июль 1917 года
```

Если известен только год:

```text
1998 год
```

Если границы относятся к разным годам:

```text
17 ноября 1991 года — 31 марта 1995 года
```

Если известны только годы:

```text
1991–1995 годы
```

Продолжительное событие размещай в файле года его начала.

Не дублируй его в файлах промежуточных лет или года окончания.

В этих файлах создавай отдельные записи только для самостоятельных событий или существенных этапов продолжительного процесса.

### Приблизительная дата

Если точная дата неизвестна, указывай доступную степень точности:

```text
начало 1998 года
```

```text
весна 1998 года
```

```text
около 1998 года
```

Приблизительность обязательно поясняй в тексте события.

Не заменяй неизвестную дату вероятной или типичной датой.

### Прекращение полномочий

Если окончание полномочий сопровождалось самостоятельным исторически значимым действием, создай отдельное событие по дате окончания:

* отставка;
* увольнение;
* смещение;
* смерть должностного лица;
* упразднение должности;
* решение государственного органа;
* официальное прекращение деятельности.

Не объединяй назначение и отставку в один период только потому, что между этими событиями человек занимал должность.

Не создавай отдельное событие окончания продолжительного процесса, если окончание уже включено в период и не являлось самостоятельным историческим действием.

### Старый и новый календарные стили

Для дореволюционных событий, к которым применимы старый и новый стили, указывай обе даты:

```text
1 (14) марта 1917 года
```

Для периода:

```text
3 (16) июня — 24 июня (7 июля) 1917 года
```

Сначала указывай дату по старому стилю, затем дату по новому стилю в скобках.

Не смешивай разные способы обозначения календарного стиля внутри одного файла.

## 5. Ограничения текущего парсера дат

Используй `timeline.py` как единственный способ вставки.

Если скрипт не распознаёт корректно оформленную дату или период:

1. Не вставляй событие вручную.
2. Не заменяй правильную дату упрощённой или выдуманной датой только ради прохождения парсера.
3. Не выдавай неуспешную вставку за выполненную.
4. Сообщи точную строку даты, которую скрипт не смог распознать.
5. Сохрани подготовленное содержимое `tools/event.md`.

Поддержку нового формата даты следует отдельно добавить в `tools/timeline.py`.

## 6. Формат события

Каждый файл `tools/event.md` оформляй следующим образом:

```markdown
#### [Краткое название события]

**[Ключевая фигура, орган, документ, процесс или событие]** [прямо укажи, что произошло].

[Один–три поясняющих абзаца.]

[При необходимости — уточнение датировки, статуса, версии или трактовки.]

[При необходимости — источник.]
```

Заголовок `####` должен кратко различать событие среди других событий той же даты.

Примеры:

```markdown
#### Назначение Евгения Примакова директором Центральной службы разведки СССР
```

```markdown
#### Начало пикета воркутинских шахтёров у Дома правительства
```

```markdown
#### Подписание Беловежских соглашений
```

Не помещай дату в заголовок `####`, если она уже передаётся через параметр `--date`.

---

## 7. Основное утверждение

После заголовка `####` дай основное содержание события в одном или двух предложениях.

В первом предложении обязательно выдели ключевую фигуру, орган, документ, процесс или событие **жирным**.

Для события конкретного дня:

```markdown
**Владимир Путин** был назначен директором Федеральной службы безопасности России.
```

Для продолжительного события:

```markdown
**Воркутинские шахтёры** провели продолжительный пикет у Дома правительства в Москве.
```

В первом предложении прямо называй, что произошло.

Не начинай событие:

* с общего контекста;
* с оценки эпохи;
* с отдалённых предпосылок;
* с биографического введения;
* с публицистического вывода.

Не выделяй жирным целый абзац.

Жирным выделяется только ключевая фигура, организация, документ, событие или короткая смысловая конструкция.

### Не повторяй дату внутри события

Если дата или период полностью указаны в заголовке `###` и относятся ко всему событию, не повторяй их в первом предложении и последующем тексте без смысловой необходимости.

Заголовок отвечает на вопрос, когда произошло событие. Первое предложение должно сразу сообщать, что произошло и каков был непосредственный результат.

Неправильно:

```markdown
### 16 июня 1996 года

#### Первый тур президентских выборов

**Первый тур президентских выборов в Российской Федерации** состоялся 16 июня 1996 года.
```

Правильно:

```markdown
### 16 июня 1996 года

#### Первый тур президентских выборов

**Первый тур президентских выборов в Российской Федерации** не выявил победителя: ни один из кандидатов не получил более 50 % голосов, поэтому был назначен второй тур.
```

Повтор даты допустим только тогда, когда она выполняет отдельную смысловую функцию:

* сопоставляется с другой датой;
* обозначает внутренний этап продолжительного события;
* уточняет разницу между фактическим действием и официальным оформлением;
* необходима для объяснения спорной или неоднозначной датировки.

Не повторяй дату только ради грамматической полноты предложения.

## 8. Пояснение события

После основного утверждения добавляй от одного до трёх связных абзацев.

Раскрывай только необходимые аспекты:

* что именно произошло;
* кто участвовал;
* каким документом или решением событие было оформлено;
* почему событие было важно;
* каков был непосредственный исторический, политический, социальный или экономический контекст;
* к каким ближайшим последствиям событие привело;
* чем завершился продолжительный процесс;
* какие существуют уточнения по статусу, трактовке или датировке.

Не пытайся обязательно раскрыть все аспекты.

Не перегружай событие:

* полной биографией участников;
* общей историей эпохи;
* отдалёнными последствиями;
* сведениями, которые не помогают понять конкретное событие.

Если событие является частью продолжительного процесса, кратко обозначь этот процесс, но не превращай одну запись в полную историю всего периода.

## 9. Неопределённость и трактовки

Если дата спорная, приблизительная или неточная, либо источники расходятся, укажи это отдельной фразой:

```text
Точная дата принятия решения неизвестна.
```

```text
В источниках встречаются разные даты начала события.
```

```text
Дата относится к официальному объявлению; фактические действия начались ранее.
```

Сохраняй различие между:

* установленным фактом;
* официальной версией;
* свидетельством участника;
* предположением;
* политической оценкой;
* позднейшей интерпретацией;
* причинной реконструкцией.

Не представляй версию, слух, оценку или причинную реконструкцию как установленный факт.

Используй точные формулировки:

```text
По официальной версии...
```

```text
Следствие пришло к выводу...
```

```text
Современники выдвигали предположение...
```

```text
Эта трактовка не получила документального подтверждения.
```

Не приписывай участникам намерение, подготовку или скрытую цель, если это прямо не подтверждено источниками.

---

## 10. Стиль

Используй историко-энциклопедический стиль:

* ясно;
* плотно;
* содержательно;
* без воды;
* не телеграфно.

Сохраняй стиль исторической хроники, а не публицистики.

Не используй:

* эмоционально окрашенные формулировки;
* риторические вопросы;
* обращения к читателю;
* морализаторские выводы;
* канцелярские вводные конструкции без необходимости;
* повторение одной мысли разными словами;
* таблицы;
* списки внутри исторического события.

Пояснение оформляй связными абзацами.

Важную цитату можно оформить как Markdown-цитату:

```markdown
> «Цитата»
```

Используй цитату только тогда, когда она помогает понять событие, позицию участника или содержание документа.

---

## 11. Источники и ссылки

Источники не являются обязательной частью каждого события.

Добавляй источники, если:

* они предоставлены в исходных данных;
* отдельно запрошен поиск источников;
* источник необходим для подтверждения точной даты;
* необходимо сослаться на закон, указ, постановление, договор или другой документ;
* речь идёт о спорном факте, версии, цитате или неоднозначной трактовке.

Если источники не предоставлены и поиск не запрошен, не придумывай:

* ссылки;
* названия публикаций;
* реквизиты документов;
* фиктивные архивы;
* несуществующие источники.

### Встроенная ссылка

Если источник подтверждает конкретное утверждение, встраивай ссылку непосредственно в соответствующие слова:

```markdown
Назначение было оформлено [Указом Президента РФ от 25 мая 1998 года № 575](https://example.com).
```

### Источник в конце события

Если публикация или документ служит основанием для всего события:

```markdown
Источник: [Название публикации или документа](https://example.com)
```

Если источников несколько:

```markdown
Источники: [Первый источник](https://example.com), [второй источник](https://example.com)
```

Не дублируй источник одновременно встроенной ссылкой и отдельной строкой.

Не используй голый URL.

Неправильно:

```text
https://example.com
```

Правильно:

```markdown
Источник: [Название публикации](https://example.com)
```

Не используй бессодержательные подписи:

```text
[ссылка]
[здесь]
[читать]
```

Ссылка должна стоять на названии документа, публикации, архива, организации или материала.

Если источник подтверждает только часть абзаца, размести ссылку рядом с соответствующим утверждением.

Не создавай общий список литературы в конце годового файла, если это не запрошено отдельно.

## 12. Отчёт после выполнения

После успешного добавления кратко сообщи:

* какое событие добавлено;
* какая дата использована;
* в какой файл оно добавлено;
* какой командой вызван скрипт;
* прошла ли проверка `git diff`;
* были ли автоматически переставлены ранее существующие блоки.

Не вставляй в ответ полный текст годового файла.

Не утверждай, что событие добавлено, пока команда не была успешно выполнена и результат не был проверен.

Если у тебя нет доступа к командной строке, прямо сообщи об этом и предоставь:

1. готовое содержимое `tools/event.md`;
2. точную команду для запуска.

Не выдавай подготовленную команду за уже выполненную операцию.
